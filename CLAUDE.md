# LaJocondeJumelle — instructions for Claude Code

## Prisma migrations (backend/prisma)

- After any change to `backend/prisma/schema.prisma`, create the migration **on the development
  database only** (local `DATABASE_URL`, `localhost:5433`, see `backend/.env`):

  ```text
  npm exec -w backend -- prisma migrate dev --name <explicit_name>
  ```

  then check:

  ```text
  npm exec -w backend -- prisma migrate status
  ```

  Expected: "Database schema is up to date!". The Prisma client is regenerated by `migrate dev`.
- **Never** modify a migration that has already been applied (folder present in
  `backend/prisma/migrations/` and listed by `migrate status`): create a new migration.
  A migration modified after being applied breaks Prisma's integrity check in
  development and in production.
- Write each `migration.sql` in one go, complete: the project's hook applies it as soon as
  a file `backend/prisma/migrations/**/*.sql` is created or modified (see below).
- If `migrate dev` offers to reset the database ("reset"), refuse and report the drift:
  never wipe the development database without explicit agreement.
- Never run `migrate dev`, `migrate reset` or `db push` against any database other than the local one.
  In production, only `prisma migrate deploy` runs, via `deploy/api-entrypoint.sh`, after
  a recent backup.
- The project's migrations come with a `down.sql` (manual rollback, see
  `backend/prisma/migrations/0002_coverage/down.sql`).
  - **Exemption: `0001_init` has no `down.sql`.** It creates the whole initial schema; its only
    possible rollback would drop every table, which is a database restore, not a rollback. To go
    back before `0002`, restore the backup taken before the migration. Do not add a `down.sql`
    there, and do not edit its applied `migration.sql`.
  - `0003` and `0007` have a `down.sql` (added after the fact). Roll migrations back in reverse
    order: each `down.sql` states what must be rolled back first.

## Project hooks (.claude/settings.json)

- `SessionStart` and `PostToolUse` (on `backend/prisma/migrations/**/*.sql`) run
  `.claude/hooks/apply-migrations.js`, which runs `npm run -w backend prisma:deploy` **only**
  if the targeted database is local (`localhost`, port 5433) and outside `NODE_ENV=production`. Otherwise it
  does nothing and says so. On failure, it prints the error and exits with code 2.
