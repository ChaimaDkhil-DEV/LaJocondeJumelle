# REST contract – Phase 1

**Base**: `/api` (same origin as the SPA). **Format**: JSON, except uploads
(`multipart/form-data`) and downloads (binary). The executable contract (OpenAPI) is
generated by the backend; this document fixes its expected content.

## Common rules

- **Authentication**: `sid` session cookie (`HttpOnly`, `Secure`, `SameSite=Strict`).
  All routes except `POST /auth/login` require it → otherwise `401 UNAUTHENTICATED`.
- **Modifying requests**: `Origin` header equal to the application domain, otherwise `403`.
- **Validation**: allow-listed DTOs; an unknown or invalid field → `400 VALIDATION_ERROR`
  with the list of fields in error.
- **Access**: resource not visible → `404 NOT_FOUND` (does not reveal that it exists); forbidden
  action on a visible resource → `403 FORBIDDEN`. Both are logged
  (`ACCESS_DENIED`).
- **Error format**:
  `{ "error": { "code": "INVALID_TRANSITION", "message": "<readable French text>", "details": {…} } }`
- **Business codes**: `INVALID_TRANSITION` (409), `STATE_CHANGED` (409, optimistic locking),
  `RECIPIENT_NOT_ALLOWED` (422), `ASSIGNEE_REQUIRED` (422: approval with manual assignment
  and no employee chosen), `PHOTO_REQUIRED` (422), `REASON_REQUIRED` (422),
  `CONTENT_REQUIRED` (422: neither voice message nor description), `FILE_TYPE_NOT_ALLOWED` (415),
  `FILE_TOO_LARGE` (413), `VOICE_TOO_LONG` (422), `VOICE_TOO_SHORT` (422),
  `PASSWORD_CHANGE_REQUIRED` (403), `RATE_LIMITED` (429).
- **Clock**: every response carries the `X-Server-Time` header (ISO 8601), used for
  countdowns.
- **Pagination**: `?cursor=<opaque>&limit=25` → `{ items: [...], nextCursor: string | null }`.

## Authentication

| Method | Route | Access | Body / response |
|--------|-------|--------|-----------------|
| POST | `/auth/login` | public, rate-limited: 5/min per (IP, username), then 10 failures per username and 100 failures per IP over 15 min (successes do not count) | `{ username, password }` → `200 { user }` + cookie; `401` generic message; `429 RATE_LIMITED` when blocked |
| POST | `/auth/logout` | logged in | `204`; the session's sockets are closed |
| GET | `/auth/me` | logged in | `{ id, displayName, role, permissions[], mustChangePassword }` |
| POST | `/auth/password` | logged in | `{ currentPassword, newPassword }` → `204` (12 characters minimum) |

As long as `mustChangePassword` is true, only `/auth/*` responds; the others return
`403 PASSWORD_CHANGE_REQUIRED`.

## Requests

| Method | Route | Access | Body / response |
|--------|-------|--------|-----------------|
| GET | `/requests` | logged in (visibility filter) | filters: `status[]`, `priority[]`, `categoryId[]`, `assigneeId`, `requesterId`, `from`, `to`, `overdue`, `q` (title, case-insensitive, 120 characters at most), `scope` (`mine`, `assigned`, `managed`, `all`); `from`/`to` in ISO 8601, bounds included (a date alone covers the whole day); `overdue` = `true`/`false` → paginated list of `RequestSummary` |
| POST | `/requests` | `REQUEST_CREATE` + authorized category | `{ clientId, title, description?, voiceFileId?, categoryId, priority, recipientId?, asDraft? }` → `201 RequestDetail`; resending the same `clientId` → `200` with the existing request |
| GET | `/requests/:id` | read access authorized | `RequestDetail` |
| PATCH | `/requests/:id` | requester, status DRAFT | edit the draft's fields |
| DELETE | `/requests/:id` | requester, status DRAFT | `204` (T19) |
| POST | `/requests/:id/actions` | according to the state machine | `{ action, version, reason?, assigneeId?, proofFileIds? }` → `200 RequestDetail` |
| PATCH | `/requests/:id/priority` | `CHANGE_PRIORITY` in `allowedActions` (see data-model §State machine), otherwise `403` | `{ priority, version }` → `200 RequestDetail`; same priority → `400`; stale version → `409 STATE_CHANGED`; the running deadline is recalculated from the start of the stage with the new priority's duration (data-model §Deadlines) |
| GET | `/requests/:id/assignees` | user who can approve or reassign the request (otherwise `403`) | active employees among the category's recipients: `[{ id, displayName, jobTitle }]` |
| GET | `/requests/:id/history` | read access authorized | chronological list `{ id, type, actor{id,displayName}|null (null = system), fromValue, toValue, comment, createdAt }`; values containing `assigneeId` also carry `assigneeName` |

`action` ∈ `SUBMIT`, `APPROVE`, `REJECT`, `DECLINE`, `CANCEL`, `ACCEPT`, `START`, `COMPLETE`,
`CLOSE`, `VALIDATE_FINAL`, `REQUEST_CORRECTION`, `RESUME`, `REASSIGN`.
`reason` is required for `REJECT`, `DECLINE`, `REQUEST_CORRECTION`; `assigneeId` for
`APPROVE` (manual assignment) and `REASSIGN`; `proofFileIds` for `COMPLETE` if a photo is required.

**RequestSummary**: `id, reference, title, category{id,name}, priority, status,
requester{id,displayName}, assignee{id,displayName}|null, createdAt, currentStage,
currentDueAt, warnAt, overdueStage, hasVoice, unreadCount`.

**RequestDetail**: RequestSummary + `description, voice{fileId,durationSeconds}|null,
rulesSnapshot{circuit, photoRequired, closureMode, finalValidation, assignmentMode}, timestamps{…}, version,
rejectionReason, allowedActions[]` (computed by the access policy for the current
user: the only source for displaying buttons), `proofPhotos[{fileId}]` (proof photos),
`canWriteInThread` (the thread's reply form is shown only if it is true).

## Discussion thread

| Method | Route | Access | Body / response |
|--------|-------|--------|-----------------|
| GET | `/requests/:id/messages` | read access authorized | paginated list, newest to oldest: `{ id, kind, author{id,displayName}|null, text, voice{fileId,durationSeconds}|null, attachments[{fileId,kind,mimeType,originalName,sizeBytes}], createdAt }` |
| POST | `/requests/:id/messages` | participant, status neither draft nor final (otherwise `403`) | `{ clientId, text?, voiceFileId?, attachmentFileIds? }` → `201`; idempotent per `clientId`; at least one text, voice message or attachment (`422 CONTENT_REQUIRED`); at most `attachmentMaxPerMessage` attachments; files uploaded by the author and not yet used. ## Files

| Method | Route | Access | Body / response |
|--------|-------|--------|-----------------|
| POST | `/files` | logged in | `multipart`: `file`, `kind` (`VOICE`, `PHOTO`, `DOCUMENT`), `requestId?` → `201 { id, kind, mimeType, sizeBytes, durationSeconds? }`. Without `requestId` (creation in progress), the file is temporary and attached when the request is created; deleted if not attached within 24 h. |
| GET | `/files/:id` | read access authorized on the parent request (or author of a temporary file) | binary; `Range` requests accepted (`206`); headers: stored type, `nosniff`, `Cache-Control: private, no-store`, `Content-Disposition` |

Processing: voice message → ffprobe + AAC/MP4 conversion; photo → sharp (metadata stripped);
document → magic-byte check only. Errors: `FILE_TYPE_NOT_ALLOWED`,
`FILE_TOO_LARGE`, `VOICE_TOO_LONG`, `VOICE_TOO_SHORT`.

## Administration (super administrator only)

| Method | Route | Object |
|--------|-------|--------|
| GET, POST | `/admin/users` | list, create (temporary password returned only once) |
| PATCH | `/admin/users/:id` | name, job title, role, activation |
| POST | `/admin/users/:id/reset-password` | new temporary password |
| GET, PUT | `/admin/role-permissions` | permissions per role |
| GET, POST | `/admin/categories` | list, create |
| PATCH | `/admin/categories/:id` | workflow, modes, photo, activation |
| PUT | `/admin/categories/:id/recipients` | `{ userIds[] }` |
| PUT | `/admin/categories/:id/managers` | `{ userIds[] }` (role MANAGER or SUPER_ADMIN) |
| GET, PUT | `/admin/categories/:id/deadlines` | rules per priority |
| GET, PUT | `/admin/settings` | global settings |
| GET | `/admin/audit` | filters `actorId`, `action`, `from`, `to`; read-only |

All these routes return `403 FORBIDDEN` (audit `ACCESS_DENIED`, reason `NOT_SUPER_ADMIN`) to any other role.

Details:

- **Accounts**: `username` normalized to lowercase, 3–64 characters `[a-z0-9._-]`, unique (`409`).
  Creation and reset return `{ temporaryPassword }` only once; the account must
  change it at the next login. Deactivation and reset close all the account's sessions
  (`session:ended`). The super administrator can neither deactivate themselves, nor lose their role,
  nor reset their own password (`400`).
- **Categories**: `name` unique, case-insensitive (1–60). In workflow A, `finalValidation`
  must be false, `assignmentMode` `MANUAL` and no validation deadline is accepted.
  `assignmentMode = AUTO` requires `autoAssigneeId` among the recipients (set the recipients
  first). A new category receives the provisional default deadlines.
- **Deadlines**: `PUT` expects exactly 4 rules (one per priority), each an integer duration from 1 to 525,600
  minutes or `null` (no deadline).
- **Permissions per role**: `{ EMPLOYEE: Permission[], MANAGER: Permission[] }` among `REQUEST_CREATE`,
  `PRIORITY_CHANGE_OWN`, `PRIORITY_CHANGE_MANAGED`, `REQUEST_REASSIGN`; the super administrator always has everything.
- **Settings**: partial update; unknown key or out-of-range value → `400` for the whole request.
  One `SETTING_CHANGED` audit per setting actually changed.
- **Audit**: cursor pagination (`limit` ≤ 100), most recent first; `to` as a date
  alone covers the whole day.

| Method | Route | Object |
|--------|-------|--------|
| GET | `/settings/client` | any logged-in user: `voiceMaxSeconds`, `attachmentMaxBytes`, `attachmentMaxPerMessage`, `draftsEnabled` |

Every administration write produces an `AuditLog` entry with the before/after values.
Changes to categories and deadlines apply only to new requests.
